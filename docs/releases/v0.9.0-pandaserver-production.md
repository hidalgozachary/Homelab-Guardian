Each scheduled execution is disposable. The Guardian container exits after completing collection, scoring, persistence, and notification handling.

## Kernel Health Monitoring

Version 0.9.0 introduces read-only kernel-health monitoring using `dmesg`.

Guardian detects high-signal events including:

- Kernel faults
- Oops events
- Kernel panics
- Page faults
- RCU stalls
- Machine Check and hardware errors
- EDAC errors
- Out-of-memory events
- BTRFS errors
- XFS errors
- I/O errors
- NVMe errors and timeouts
- Disk and controller resets

Benign initialization messages such as:

    MCE: In-kernel MCE decoding enabled.

are intentionally excluded from hardware-error scoring.

## SMART Monitoring

Guardian now monitors assigned ATA and NVMe devices through `smartctl`.

ATA reporting includes:

- Overall SMART health
- Temperature
- Power-on hours
- Reallocated sectors
- Pending sectors
- Offline uncorrectable sectors

NVMe reporting includes:

- Overall health
- Temperature
- Power-on hours
- Media errors
- Critical warning state
- Endurance percentage used

Device-access failures are handled as unavailable data rather than crashing Guardian.

## Docker Intelligence

Docker monitoring now includes container inspection and restart-history awareness.

Guardian records:

- Container state
- Health-check state
- Exit code
- Lifetime restart count
- Restart delta since the previous report

Historical restart counts are not treated as active failures.

For example, if a container has six historical restarts and remains at six during the next report:

    restart_count = 6
    restart_delta = 0

no warning is produced.

A new restart causes:

    restart_delta > 0

and is surfaced as a current operational issue.

## Persistent Health History

Every scheduled execution writes a timestamped JSON health report.

Production configuration retains reports for 30 days.

Only files matching the Guardian health-report naming contract are eligible for retention cleanup.

## Discord Alerting

Discord is the primary production alert channel for v0.9.0.

Production behavior:

- HEALTHY reports are saved but not sent to Discord
- WARNING reports are sent to Discord
- CRITICAL reports are sent to Discord

Webhook credentials are stored outside source control in a protected environment file.

## Scheduled Deployment

PandaServer uses Unraid User Scripts to execute Guardian hourly.

The production launcher:

- Uses the validated `homelab-guardian:prod` image
- Prevents overlapping executions with `flock`
- Writes persistent run logs
- Preserves JSON report history
- Loads secrets from a protected `.env` file
- Removes the temporary Guardian container after each run
- Returns the Guardian health exit code to the scheduler

## Security and Safety

Homelab Guardian remains read-only by default.

Version 0.9.0 does not:

- Restart containers automatically
- Stop containers
- Delete containers or images
- Modify Unraid array assignments
- Start SMART tests automatically
- Repair filesystems
- Expose PandaServer publicly
- Commit secrets to Git
- Perform automatic remediation

## Rollback

The scheduled deployment can be disabled by turning off the Homelab Guardian User Script schedule in Unraid.

The production image can be replaced with a previously validated image if rollback is necessary.

Persistent JSON reports and logs remain outside the temporary Guardian container.
